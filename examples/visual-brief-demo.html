visual-brief · skill demo · meta edition

Your spec is complete.
So why does nobody get it?

This page explains the visual-brief skill — and is itself an output of it

✕ What we hand off today

Reference card: every fact, equal weight, jargon chips. Technically complete. Humanly unreadable — the kamrai brief v1 got the verdict "difficult to understand, difficult to communicate with human."

✓ What this skill produces

Story scroll: one visceral hook (a sale that flips from +$107 to −$22), ≤6 plain-language beats, technical detail demoted below an explicit divider. Same facts, ruthless hierarchy.

01 · The problem

Specs optimize for completeness, readers need hierarchy

⚖️
Every fact gets equal weightA reader can't tell the one number that matters from the forty that don't. Completeness without hierarchy is noise.
🏗️
Docs lead with architectureBoxes and arrows before the reader feels the problem. Nobody cares how it works until they care that it exists.
🗣️
One artifact, two audiencesDevs want file paths and event names; stakeholders want the story. A doc tuned for either loses the other.
02 · The workflow

Distillation is the work — HTML is the easy part

1
Pin the audiencedevs / mixed / non-technical — sets the jargon budget and the appendix split
2
Find the one "aha"the moment a reader feels the problem — best as real numbers with a contrast flip, never an architecture diagram
3
Mine real data from the sourcenumbers come from the repo, ticket, or spec — verified arithmetic, never invented demos
4
Map ≤6 beats to visual idiomsone idea per section, one idiom per beat, everything else demoted to the appendix
5
Render, screenshot, deliverbuild from the skeleton, verify with headless Chrome, ship file + preview PNG with source-of-truth links

04 · The guardrails

Six anti-patterns — each one observed in a real failed brief

Reference-card density✕ every fact at equal weight
✓ cut, or demote to appendix
Leading with architecture✕ boxes and arrows as the opener
✓ reader feels the problem first
Jargon in the story half✕ HITL, DEV DONE, event names up top
✓ plain words top, jargon appendix
Invented numbers✕ plausible-looking demo data
✓ mined from source, arithmetic checked
Mono-font body text✕ whole sections in monospace
✓ mono for labels, code, data only
More than ~6 beats✕ a wiki page pretending to scroll
✓ one aha, few beats, hard appendix cut

A3Design decisions (locked)

What this skill is not

  • Not a slide deck generator — single scrolling page only
  • Not a source of truth — footer always links the ticket/ADR
  • Not themeable — locked palette makes briefs recognizable
  • Not a build artifact — no bundler, Google Fonts only external dep

Constraints

  • Tabs/toggles allowed, but page must read stacked if JS stripped (no-js fallback)
  • English default; chain language skills (e.g. kien-thai) when content language differs
  • Dark emphasis cards: max 2 per page or they stop landing
