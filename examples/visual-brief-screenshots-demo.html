01 · THE IDIOM

A screenshot frame names the screen and says what to notice

Chrome-bar dots signal "this is a screen, not a diagram". The caption is for intent — never describe what's already visible.

02 · BEFORE / AFTER

Pair two shots when the change is the story

Redesigns, design-vs-prod gaps, migration states — put them side by side and the diff explains itself.

03 · SCOPE

What shipped, what deliberately didn't

The boundary line is what review should debate — so it's drawn explicitly.

In scope (this change)

  • Base64 data-URI embed — brief stays one file
  • Compression guardrails: ≤300 KB/image, ≤1 MB page
  • Before/after pairing via .shot-grid
  • ✓ in-scope marker for paired scope panels

Out of scope

  • Annotation pins on screenshots (CSS overlay — later)
  • Figma API auto-export (manual export works)
  • Lightbox / zoom (native scroll is enough)

Open questions

  • Should examples/ renders auto-regenerate when the skill changes?

Open risks

  • Page weight creep — 3 embedded shots ≈ 560 KB base64; the cap exists, the discipline must too

Technical detail below

Embed rules, commands, and what changed in the skill.

A1Embed rules

Inline as base64 data URI, never external URLs. JPEG for photos, PNG for crisp UI text. Set width/height to avoid layout shift. Never mock up a fake screenshot — same rule as invented numbers.

Compression commands 
sips -Z 1200 shot.png --out shot-small.png            # macOS resize
magick shot.png -resize 1200x -quality 80 shot.jpg     # ImageMagick
base64 -i shot-small.png | wc -c                       # payload check
